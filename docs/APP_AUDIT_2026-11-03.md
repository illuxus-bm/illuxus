# App audit, 3 November 2026

**Scope:** mobile app readiness, correctness, performance and code health, on `main` at `3691a3b` plus
the uncommitted Capacitor work. Security is covered separately in [`SECURITY-REVIEW.md`](../SECURITY-REVIEW.md)
and isn't repeated here.

**Method:**
- Read the source.
- Typecheck, ESLint and the Vitest suite.
- A production build with source maps, to measure the bundle.
- A 20-route sweep at 390 px in app mode (Playwright, stubbed Supabase API), checking horizontal
  overflow, tap-target size and screenshots.

No live database, device or deployed environment was used. Findings that depend on one are marked
**Unverified**.

## Summary

The app holds up well on phones. None of the 20 routes swept overflows horizontally, and the event
management screens work at 390 px. The serious problems are in a few data flows, not in the layout.

## 1. Correctness

### C-1: The Guests page bypasses the real approve and check-in flows (High)

Organisers reach `/dashboard/events/:id/guests` from the "Guests" button on the Events screen's
"Next up" card, from dashboard search results, and from event moderation. It writes to
`registrations` directly:

- **Approve** sets `approval_status` only (`GuestListPage.tsx:86`). The main registrations screen also
  invokes `send-ticket-email` for each approved guest (`RegistrationsSection.tsx:862-866`). A guest
  approved from the Guests page is never sent their ticket.
- **Check in** flips `checked_in` and `checked_in_at` (`GuestListPage.tsx:93`). The main screen goes
  through `bulk_set_attendance` and `self_check_in`. Those set `attendance_state`, log
  `attendance_events` and feed the live counters (`useEventCheckinCounters.ts:48-56` counts
  `attendance_state = 'inside'`). No database trigger syncs the two: the only triggers on
  `registrations` are validation, `updated_at`, tickets-sold, person-linking, community and consent.
  A guest checked in from this page counts as checked in, but never as inside, and gets no attendance
  minutes.

**Fix:** call the same RPCs and the ticket-email invoke as `RegistrationsSection`, or retire the page
and link to the event's Registrations tab instead.

### C-2: A transient profile-load failure assigns the wrong role (High in the app)

`loadAccountType` ignores the query error. When the request fails, `data` is null, so the account
becomes `"organizer"` and `profileCompleted` becomes `false` (`AuthContext.tsx:55-57`). `ProfileGate`
then sends anyone without an org to `/complete-profile` (`App.tsx`, `ProfileGate`), and the tab bar
shows organiser tabs. On the website this needs a failed request at sign-in. In the app, a launch with
no signal or on flaky mobile data does it.

**Fix:** on error, keep the previous values (or `null`) and retry. A row that loads without an
account type can keep defaulting to organiser, as legacy accounts expect.

### C-3: Registration lists are read in one request (High, Unverified)

`RegistrationsSection.reload()` and `GuestListPage` both fetch with
`select(...).eq("event_id", id).order(...)` and no `.range()`. Supabase caps a response at 1,000 rows
unless the project's `max_rows` has been raised. `supabase/config.toml` doesn't set it, and the hosted
value wasn't checked. If the cap applies, an event with more than 1,000 registrations will:

- show only the newest 1,000 rows;
- export only those 1,000 to CSV, because `exportCsv` builds from the in-memory `filtered` list
  (`RegistrationsSection.tsx:1086`);
- compute selection and bulk actions over that partial list.

Reports already page correctly with `src/lib/reports/fetch.ts`. Use the same helper here.

### C-4: Dashboard search isn't scoped to the workspace (Medium)

`GlobalSearch` queries `events` by title with no `org_id` filter (`DashboardTopBar.tsx:57-61`). The
policy "View published events" lets any signed-in user read every published event, so results include
other organisations' events. Each result links to `/dashboard/events/<slug>`. That page looks events up
by slug with no organisation filter (`.eq("slug", id).single()`, `EventDetailPage.tsx:143`). The link
can open another organisation's event, and it fails to load at all when two organisations use the
same slug.

Separately, the attendee search interpolates the raw term into `.or("name.ilike.%q%,email.ilike.%q%")`.
A comma or parenthesis in the term (for example "Rao, Asha") breaks the filter syntax and returns
nothing.

**Fix:** add `.eq("org_id", org.id)` and link by id. Escape or quote the term in the `.or()` filter.

### C-5: Smaller issues (Low)

- **Wrong day in "Next up".** The tile renders the date in the device's timezone
  (`EventsPage.tsx`, `toLocaleDateString` / `getDate()`), while the rest of the app uses the event's
  timezone (`lib/datetime.ts`). An organiser travelling, or an event set in another zone, can see the
  wrong day.
- **Bulk check-in is one round trip per guest.** It calls `self_check_in` once per virtual row
  (`RegistrationsSection.tsx:945`, `BulkCheckInDialog.tsx:75`), and bulk approve fires one
  `send-ticket-email` invoke per registration. Both are slow for hundreds of rows, and the emails can
  hit the function's rate limit with no retry.
- **Side effects in a state updater.** `AuthContext` runs `setUser`, `setLoading` and the profile
  fetch inside a `setSession` updater function. React may call updaters twice (Strict Mode), which
  would double the fetches. Move the side effects out of the updater.

## 2. Mobile app readiness

### What's in good shape

- **No overflow.** The 20 routes swept at 390 px don't overflow horizontally: dashboard Tickets,
  Reports, Marketing, Organization, Settings, Billing, Help, event management, Guests, New event,
  Community, the public events list, event and org pages, Discover, My events, ticket, Applications,
  Communities and Settings.
- **Tap targets are mostly large enough.** Most screens have at most one control smaller than
  28 px. Reports has 8 and New event has 4.
- **Most webview gaps are already handled.** Downloads, the share sheet, external links,
  `target="_blank"` (55 uses), the Android back button and the keyboard are covered by
  `src/lib/native/boot.ts`. `alert`, `confirm` and `prompt` are implemented by Capacitor on both
  platforms.
- **Camera.** The QR scanners request the rear camera (`facingMode: "environment"`) and the manifests
  declare camera permission.

### M-1: Printing doesn't work in the app (Medium)

`printBadges` and `printCalibration` open an empty popup, write HTML into it and call `print()`
(`print-badges.ts:505,524`). The web view has no popups, so `window.open("")` returns `null` and the
user sees the "popup-blocked" error. The "Print" buttons on Contact and support-ticket tracking call
`window.print()`, which does nothing in either web view.

**Fix:** in the app, route printing to the badge PDF export (already in `badge-export.ts`) and the
share sheet, which has Print. Hide the plain "Print" buttons.

### M-2: Opening the public page from the editor fails in the app (Medium)

The event editor opens a blank tab first and navigates it later, to dodge popup blockers
(`EventPageForm.tsx:328-331`). In the app, `window.open("")` returns `null`. The fallback
`window.open(href)` then goes through the in-app router, so it does still work, but only after the
save completes, with no feedback in between.

**Fix:** skip the blank-tab trick when `isNativeApp()`.

### M-3: Host controls only appear on hover (Medium)

Webinar chat delete and Q&A pin/answer (`WebinarSidebar.tsx:261,376`), and Replace/Remove on cover
and banner pickers (`EventCoverPicker.tsx:141`, `EventBannerPicker.tsx:140`), use
`opacity-0 group-hover:opacity-100`. On a phone they are invisible until tapped blind.

**Fix:** show them always below `md`, or behind a "⋯" menu.

### M-4: Things to verify on real devices (Unverified)

- **Webinars.** Agora and LiveKit need WebRTC in WKWebView (iOS 14.3+) and an Android web view
  permission grant. The microphone and camera permission strings are set, but nobody has tested a
  stage on a device. Audio stops when the app is backgrounded.
- **QR scanning.** `html5-qrcode` needs inline video playback in WKWebView.
- **App Store.**
  - Guideline 4.2 (minimum functionality) is a review risk for web-wrapped apps. The native share,
    downloads, haptics, tab bar and offline handling help.
  - Account deletion must be startable in the app. Profile links to `/data-deletion`. Organisers
    should find the same link in Settings.
  - Billing shows plan prices with "Start trial" and "Talk to sales". It sells nothing in the app,
    so in-app purchase rules shouldn't apply, but keep purchase links out of the iOS build.

## 3. Performance

### P-1: The landing page is in the first download (Medium)

The entry chunk is **1.2 MB minified, 366 KB gzipped**. By source size, the largest parts are:

| Part | Source size |
| --- | --- |
| Supabase client (auth, PostgREST, storage, realtime) | ~0.85 MB |
| `framer-motion` / `motion-dom` | ~0.45 MB |
| React Router | ~0.3 MB |
| Sentry core | ~0.2 MB |
| zod | ~0.15 MB |
| App code | ~0.6 MB |

The app code is mostly `LoginPage`, `App` and observability. `Index` (the landing page) and
`LoginPage` are imported eagerly (`App.tsx:26-28`). That pulls the hero, the landing story cards and
framer-motion into every start, including the iOS and Android apps, which never show the landing page.

**Fix:** lazy-load `Index` in the app build (`import.meta.env.MODE === "capacitor"`), or everywhere,
since `/` already ships prerendered meta. Keep framer-motion out of the entry. `LoginPage` could also
be lazy.

### P-2: Heavy route chunks (Low)

These load only when used, which is fine. They are worth knowing about for mobile data:

| Chunk | Size |
| --- | --- |
| `AgoraWebinarStage` | 1.58 MB |
| `excel` (exceljs) | 940 KB |
| `StageCanvas` | 892 KB |
| `WebinarStage` | 586 KB |
| `EventDetailPage` | 575 KB |
| `jspdf` | 419 KB |

`EventDetailPage` is the organiser's most-used screen. Splitting its tabs into lazy chunks would help
there most.

### P-3: Query shape (Low)

There are 77 `select("*")` calls. The worst is `RegistrationsSection.reload()`, which pulls every
column of every registration for the list (C-3).

There are 35 realtime `.channel(` subscriptions against 38 `removeChannel` / `unsubscribe` calls, so
cleanup looks consistent. No unbounded query-in-a-loop was found beyond the bulk paths in C-5.

## 4. Code health

### Type errors: 110, and CI doesn't block on them

Most come from `src/integrations/supabase/types.ts`, which covers 74 tables while the schema creates
108. Missing tables (`community_members`, support-ticket and messaging tables) type as `never`. That
accounts for nearly all errors in SupportTicketsPage (23), MarketingPage (21) and CommunicationSection
(19). Regenerating the file (`supabase gen types typescript`) should clear most of them.

The rest are real mismatches worth a look:

- **Dead `dashboardblocks` code that wouldn't work if used.** `src/components/dashboardblocks/chart.tsx`
  and `forecast.tsx` import recharts 3 APIs (`useXAxisScale`, `usePlotArea`, `useActiveTooltipLabel`,
  `TooltipContentProps`). Recharts 2.15.4 is installed. Nothing outside `dashboardblocks` imports these
  blocks, so users aren't affected. See dead code below.
- **Editor sections with no matching type.** `EventPageForm.tsx:890-1006` switches on section ids
  (`workshops`, `exhibitors`, `travel`, `codeOfConduct`, `newsletter`, `press`, `partners`,
  `liveStream`) that the section type doesn't include. Either the type is stale or those branches
  can't be reached.
- **Unknown badge preset.** `badge-design.ts:297` uses preset `"horizontal-banner"`, which isn't a
  `LayoutPresetId`. A badge using it may fall back to the default layout.
- **Type-level only:**
  - `ReportsSection.tsx:348-351` reads speaker fields missing from `SpeakerRow`.
  - `EventDetailPage.tsx:101,985` declares `Registration` twice.
  - `funnel-01.tsx:74` uses Button size `"xs"`, which doesn't exist.

### Lint: 140 errors and 131 warnings, not blocking in CI

- 111 `react-refresh/only-export-components` (fast-refresh only).
- 106 `no-explicit-any`.
- 15 `exhaustive-deps`. These are the ones worth reading: stale closures cause real bugs.
- 12 `no-console`.

Hot spots: `RegistrationsSection.tsx` (14), `PublicEventRenderer.tsx` (8), the webinar `AnalyticsPanel`
and `PreJoinCheck` (7 each), and `OrganizationManagementPage` (7).

`.github/workflows/ci.yml` blocks on tests, the build, the inlined-function check and critical
advisories. Typecheck, lint and high-severity advisories are report-only. Suggested order:

1. Regenerate DB types.
2. Make typecheck blocking.
3. Make lint blocking for errors only, after fixing `exhaustive-deps` and `no-console`.

## Fixed after the audit

C-1 to C-4 were fixed on 3 November. Each was checked against a stubbed API in the browser, recording
the requests sent.

- **C-1: the Guests page uses the real flows.**
  - Approving updates the row, then invokes `send-ticket-email`, with the same success and failure
    messages as the Registrations tab.
  - Check-in and check-out go through `toggle_attendance`. The row is then re-read, and the button
    reads "Check out" while the guest is inside.
- **C-2: a failed profile load no longer guesses.**
  - `checkAdminRole` and `loadAccountType` retry twice (after 1 s, then 2 s).
  - On a lasting failure they keep the last known values, so `ProfileGate` waits instead of
    redirecting, and they try again when the device comes back online.
  - With the profile request failing, the old code sent an attendee to `/complete-profile`. The new
    code stays on the page.
  - The Supabase client already retries 503 and 520 by itself, so this mainly matters for other
    errors and for no network at all.
- **C-3: the registrations list and the Guests page load every row**, page by page through
  `fetchAllRows`, with a stable `created_at, id` order. With 1,250 stubbed guests, both pages were
  requested and all rows shown. The UTM tripwire hash for `RegistrationsSection.tsx` was re-audited
  and bumped.
- **C-4: dashboard search is scoped to the active workspace.**
  - Events are filtered by `org_id` and guests by their event's `org_id`. A super admin outside any
    workspace keeps the platform-wide search.
  - Results link by event id.
  - The attendee search term is sent quoted, so "Rao, Asha" is matched as text.

## Fixed during this audit

- **H-1: `package-lock.json` is back in sync with `package.json`.** It now includes the Capacitor
  packages (160 added). No existing package version changed except `semver` 7.7.2 → 7.8.6, which the
  new dev tooling pulled in. Before the fix, `npm ci` (used for Vercel's API routes and by
  `npm audit` in CI) would have rejected the lockfile.
